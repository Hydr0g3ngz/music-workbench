# 产品与开源发布路线图

> 历史参考：原 Music Studio 歌曲分析流程或拆分前版本。当前工作台请从 [安装与入门](README.md) 开始；原分析产品见 [Music Studio](https://github.com/Hydr0g3ngz/music-studio)。本页的功能、命令与测量按所述旧版本解释。

[English](roadmap.en.md)

Music Studio 的核心场景是导入一首歌、得到可以同步试听的歌词/主旋律/伴奏，并修正歌词错误。发布重点是第一次能跑通、结果可以核对、导出能继续使用。

## 当时已实现

- 43 例有来源、有哈希的评测：新增中文确认录音，分开报告文字错误、时间覆盖与误差。
- 词时间补充与自然显示分句；不以删除难词或捏造逐字边界提高观感。
- 核对筛选、下一处核对、保存核对状态、单句候选比较与明确采用。
- 跟唱视图，伴奏与原唱提示音量、逐句跳转与循环试听。
- 播放独立于任务轮询，按需缓存音轨，修复反复载入与拖动暂停。
- 中英文项目说明、实际界面截图、可复现命令及贡献任务。
- 中英文可切换界面与语言记忆；45 秒免模型预计算授权示例；Windows 启动 ZIP、wheel / 源码包、校验和与发布工作流。

## 发布前与下一版

S 表示单个组件的集中修改，M 涉及多个组件，L 涉及新处理流程；它们不是交付日期承诺。

| --- | --- | --- | --- | --- |
| 已完成 | 无模型交互示例 | 安装后先体验时间轴、切轨和导出，再决定下载模型 | M | 随包提供 45 秒预计算授权示例，校验文件哈希，标明来源与机器估计性质 |
| P0 | 独立运行环境与图形化模型管理 | 从当前 Python 启动 ZIP 进一步减少安装步骤 | M | 显示缺失/已缓存模型、大小与进度；下载可恢复并校验哈希；打包后实际验证独立 worker；不静默下载大模型 |

歌词编辑仍以文字纠错为主。本阶段不扩展为完整音符编辑器、谱面排版工具或多轨 DAW；新增能力先服务于“听清楚、改对字、带走结果”。

## 借鉴的开源做法

[UVR 官方项目](https://github.com/Anjok07/ultimatevocalremovergui) 提供包含运行环境的安装包，并保留手动安装路径。该分发方式可作为独立运行环境与图形化安装的工程参考。

[ASRU 作者项目](https://github.com/navi0105/LyricAlignment) 提供可追踪的歌词标注和复现实验入口，本项目已用于新增评测。算法候选可以参考 [SOFA](https://github.com/qiuqiao/SOFA) 和 [ROSVOT](https://github.com/RickyL-2000/ROSVOT)，接入前分别核对模型许可、语言和训练重叠；该历史版本尚未评测这两个模型。

## 开源展示与反馈

README 首屏使用真实工作台截图，简要展示导入、切轨、改字、跟唱、导出，并链接实测和局限。英文入口减少读者理解成本。授权示例与预计算结果应与用户上传内容明确区分。

发布后优先收集“能否安装完成、首次试听耗时、最常见失败步骤、歌词纠错完成耗时、导出是否可用”等可操作反馈。先用自愿反馈和可复现 issue，不引入后台遥测。不要用样本数量、音符数量或 UI 的核对数量冒充准确率。

## 可独立贡献的任务

- **快捷键帮助**：增加 `?` 帮助入口，确保输入框和弹窗中的按键不误触播放。
- **导出清单**：根据实际 assets 显示可导出内容与缺失原因，验证取消后状态复位。
- **窄屏可访问性**：键盘可访问全部播放、歌词和回收站操作；检查 720p 与窄窗口遮挡。
- **翻译与可访问性**：维护 `i18n.js`，核对动态提示和屏幕阅读器文案；语言切换不能重载播放器或改动歌词。
- **中文长尾复现**：复现报告中的固定失败案例，记录替换候选和未改善情况，不修改已冻结确认集。
