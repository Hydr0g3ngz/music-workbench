## 实际改动与取舍

旋律使用持续音高状态的 Viterbi 解码，抑制短暂半音抖动，并在相邻音符间分配短暂辅音空隙。保留原始音高曲线与旧 classic 解码选项；不会把音符强制量化到节拍格。重复同音、弱声、滑音及音符止音仍是主要难点。

节拍先提取打击成分，再以更细的步长估计起音和节拍，保留原始 librosa 基线选项。和弦使用自动调音的 CQT 特征与时间平滑；词汇仍是大小三和弦/N。伴奏改为原曲减去估计人声，保证原曲能由两条音轨精确重建，额外 GPU 成本很小。

faster-whisper large-v3-turbo 的完整英文歌曲 WER 从26.7%降至23.8%，中文清唱 CER 从25.0%降至20.3%，英文清唱 WER 从9.1%降至5.5%。但完整歌曲匹配词的起点平均误差从0.356秒升至0.603秒，匹配覆盖率从78.0%升至79.6%。清唱也出现类似的时间精度取舍。因此它作为“文字优先”可选模式，默认“均衡”继续使用 small。后续实验应单独评测歌唱强制对齐，不能靠提高文字分数宣称时间更准。[faster-whisper](https://github.com/SYSTRAN/faster-whisper)。

人声活动切段的 small 在7首完整歌曲上 WER=34.6%，比整曲识别退步，未采用。这个分段方案仍可作为明确标记的实验选项，不能把论文中的收益直接当成本项目收益。

参考 [Beat This!](https://github.com/CPJKU/beat_this) 接入了可选后端，并实际运行 small0。五段 GuitarSet 的诊断 F1=92.7%，但 small0 训练过 GuitarSet，因此比较工具禁止用该诊断入选默认。官方对应验证折的权重已记录来源与校验元数据，下载端点较慢，该实验没有完成这些权重的公平对照。默认使用上面的无训练节拍改进。ROSVOT / SOFA / RoFormer 仍是后续候选，该实验没有把未完成的模型实验记成已验证结果。

## 没有隐藏的退步与限制

默认方案中，gts-01、gts-08、gts-10 的严格含止音 F1 各退步约6.1、6.7、5.1个百分点；guitarset-02 的根音与大小调成绩约退步9.6、9.7个百分点。逐例退步在 [配对比较](../benchmarks/results/comparison-balanced.json) 中明确列出。和弦改进的探索性 bootstrap 区间仍跨过0；清唱仅有4位歌手，不能据此承诺任意歌曲效果。

这套集合没有带联合词/音符真值的真实中文成品混音，分离只测两段短预览。音符分数仍偏低，尤其止音与重复同音。后续优先增加独立歌手/中文混音和长曲分离样本，再评估专门的音符转录与强制对齐模型。

## 复现与运行证据

最初的完整26例运行耗时671.7秒。发现 torchcrepe 会添加随机音高抖动后，固定 Python/NumPy/PyTorch seed=0 重提旋律，并使两种解码共享哈希一致的音高输入。一例独立进程复跑的 pitch.json 与 melody.json 哈希完全一致。最终报告继承其他未修改模块的已测预测，不能拿组合报告的几秒耗时当作整套推理加速。

本机为 RTX4070 Laptop 8GB、32GB RAM。原完整轮次 GPU 1Hz采样峰值约1033MiB，turbo歌词对照约1457MiB；都没有 OOM，但这是整卡采样值，可能漏过瞬时峰值。记录了模型修订版、权重哈希、源码快照、软件版本、输入哈希、继承来源、失败记录和逐阶段耗时。旧预览报告保留，主要结论使用当前固定 seed 的配对结果。

最终默认配置还通过网页离线分析整首132.989秒授权示例歌，耗时103.21秒，输出18句歌词、206音符、42和弦区间和261节拍；这些数量不是准确率。音频采样长度、时间边界、引用与MIDI通过完整性验证。

## 产品改动

项目增加搜索、重命名、删除、立即撤销与回收站恢复。运行中的歌曲需先停止；已删除项目重启后仍可恢复。歌词可逐句改字、保存并恢复原文；修改后的文字同步到 LRC/SRT/JSON/MIDI，原始识别文件保留。修改句暂按整句高亮，不沿用旧字词的时间与音符链接。

新增上一句/下一句与键盘定位，原曲先可播放，人声和伴奏后台载入。播放游标改为独立图层，播放过程中无需每帧重绘全部音高与波形。新增清楚的失败提示和可展开诊断信息，缩短桌面头部以给时间轴留出更多空间。自动测试覆盖核心算法、配对评分、并发写文件、项目恢复、歌词导出和模式修订版切换；真实浏览器验证记录见 [UI 验证](ui-v2-validation.md)。
