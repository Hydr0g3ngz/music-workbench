# 本地 AI：硬件、速度与流程

[English](model-hardware.en.md) · [模型安装](models.md)

CPU 能运行部分功能，但“能完成”和“等待时间适合创作”是两回事。语音降噪和短录音转写适合 CPU；分轨和单旋律提取推荐 GPU。ACE-Step 在当前 Windows 配置中要求 NVIDIA GPU，不提供 CPU 生成方案。

## 实测条件

2026-10-17，Windows x64，Core Ultra 9 185H，RTX 4070 Laptop 8 GB，32 GB RAM。
CPU 工具使用独立 Python 3.12.10、Torch 2.5.1 CPU、四个推理线程；GPU 工具使用另一套独立 Python 与 Torch 2.10 CUDA 12.8。两者使用同一版本模型与相同算法参数。

每项启动新进程，符合当前任务队列行为。时间包含进程启动、依赖导入、权重加载、推理与写文件；未清空操作系统文件缓存。30 秒音乐由有授权说明的内置乐器样本构成，23.112 秒讲话为内置 VoiceBank-DEMAND 示例。它们用于测速度，不是分轨或识别质量测试，也不是三分钟流行歌曲的速度保证。低于 1 的时长比表示处理快于音频长度。

| 任务 | 音频长度 | CPU 完成时间 | 进程峰值 RAM（采样） |
| --- | ---: | ---: | ---: |
| Demucs 四分轨 | 30 秒 | 49.6 秒 | 1336 MiB |
| CREPE 单旋律提取 | 30 秒 | 109.0 秒 | 1191 MiB |
| Whisper small 转写 | 23.112 秒 | 16.6 秒 | 855 MiB |
| DPDFNet2 语音降噪 | 23.112 秒 | 11.3 秒 | 160 MiB |
| GTCRN 语音降噪 | 23.112 秒 | 3.2 秒 | 112 MiB |

独立 CUDA 工具包在同一份冻结输入上的完成时间：四分轨 **9.1 秒**，CREPE **11.0 秒**，Whisper **11.7 秒**。GPU 实际 Torch 分配峰值分别约 553 MiB 和 735 MiB；Whisper 使用 CTranslate2，Torch 的零分配值不能解释为零显存，因此未报告其显存。每个配置仅一次测量，非统计性能排行榜。

首次几秒钟的安装验证不能替代这些测量。初始化、音频内容、温度、后台负载和硬件都会改变时间。不要将短片段测量线性外推成整首歌曲耗时。

## ACE-Step 到底是什么配置

当前固定 ACE-Step 1.5 Turbo，代码修订 `ca1e85fe9430179831e6bc6be790c332190a3866`，模型修订 `19671f406d603126926c1b7e2adc169acbcade22`。直接读取 safetensors 头部得到：

| 组件 | 检查点张量元素数（约参数量） | 磁盘文件 | 存储精度 |
| --- | ---: | ---: | --- |
| Turbo 主生成网络 | 2,393,872,518 | 4,787,825,604 字节 | BF16 |
| VAE | 168,695,426 | 337,431,388 字节 | BF16 |
| Qwen3-Embedding 文本编码器 | 595,776,512 | 1,191,586,416 字节 | BF16 |

三个权重文件合计约 6.32 GB（5.88 GiB）。安装占用还包括 Python、CUDA 运行库、模型程序与下载缓存，不能用权重大小代替完整安装大小。Qwen3-Embedding 是提示词编码器；本配置没有加载 5Hz 语言模型，也不运行 AI 编曲规划。

默认的小显存方案会在加载后，用 torchao 对 **DiT 解码器线性层的权重**执行 `int8_weight_only`。没有把全部主模型、VAE 和文本编码器转换为 INT8；下载文件也不是一个全 INT8 检查点。

dev16 的生成前检查使用实际空闲显存与 GPU 架构，不按“RTX 某型号”硬编码。自动配置使用 CUDA 12.8，需 Windows NVIDIA 驱动 570 或更新。

| 方案 | 选择条件（空闲显存） | 运行方式 |
| --- | --- | --- |
| 节省显存 | 4–10 GB | 解码器线性层 INT8，模型按阶段在内存与 GPU 之间移动 |
| 均衡 | 10–18 GB | 同样的 INT8；主生成网络保留在 GPU，其他模块按阶段移动 |
| 原始精度 | 至少 18 GB | BF16，不量化，不做 CPU 卸载 |

ACE 自动配置另要求 Ampere 或更新架构、至少 8 GB 总显存。低于 4 GB 空闲显存会提示关闭其他 GPU 程序。可在生成窗口“更多参数”手动选择方案；不足时拒绝运行，避免静默降级。阈值是资源策略，并非所有显卡和 60 秒任务的兼容性承诺。当前实际硬件验证仅覆盖 4070 Laptop 的节省显存方案，其余方案已有选择逻辑回归，仍需相应显卡实测。

本次实际生成 12 秒、8 步纯音乐：初始化与校验 78.7 秒，生成及输出 16.0 秒，合计 94.7 秒；Torch 显存分配峰值约 3150 MiB，进程驻留内存峰值约 11,292 MiB，私有提交内存峰值约 17,947 MiB。本次有安装活动，不能当作受控速度对照。内存卸载会占用大量系统内存，32 GB RAM 是实测配置。当前任务完成后退出进程释放模型，因此每次都有加载成本。

## 哪些模型真正进入了工作流

| 模型 | 用途和结果去向 | 检查与限制 |
| --- | --- | --- |
| ACE-Step | 文字生成、参考变奏、局部重绘 → 草稿试听 → 采用音频轨 → 撤销/导出 | 实际生成验证；生成的是音频，不能直接逐声部编辑音符 |
| Demucs | 两分轨/四分轨 → 试听 → 对齐替换源片段或加入轨道 | CPU、CUDA 真实推理；四分轨不等于生成四套新乐器演奏 |
| Mel-Band RoFormer KJ | 人声与伴奏 → 同样的对齐采用流程 | 已有分轨质量对照；dev17 增加自动安装独立 CUDA 工具包 |
| CREPE | 独唱/哼唱/单音乐器 → 音高、MIDI → 采用为可编辑乐器音符 | 有公开标注数据评测；不支持可靠的整曲多音扒谱，起止音仍有误差 |
| Whisper small | 语音与歌词 → 转写 → 详细素材编辑器逐行改字 → TXT/LRC/SRT | CPU/CUDA 实际运行；歌唱、背景伴奏和人声重叠更容易出错 |
| Qwen3-ASR-1.7B + ForcedAligner-0.6B | 转写 → 声学字词定位 → 同一文本修正流程 | dev17 自动安装；可选粗略时间或逐字对齐。对齐保留识别文字，不能消除错词；失败段落保留原时间并标记复核 |
| DPDFNet2 | 讲话降噪 → 原音/处理结果对照 → 加入新轨 | CPU 实测；可调强度，可能损伤音乐与环境声 |
| GTCRN | 轻量讲话降噪 → 同样的试听采用流程 | CPU 实测；内部 16 kHz，高频保留有局限，作为实验性备选 |

主工作台现在可选择运行设备、转写语言、Qwen 时间精度和降噪强度，参数会传入真实任务。处理仍针对**整份源素材**，采用时保留片段范围；缩短时间轴中的片段不会自动减少模型计算量。文本编辑当前通过“详细结果与编辑”进入单素材页面，尚未内联到多轨工作台。

节拍、速度、调性、变速变调、EQ、压缩、混响和音量曲线是 DSP；创作蓝图与段落提示词整理是规则逻辑。这些功能没有另一个隐含的 AI 模型。`stable/rest` 是同一个 CREPE 网络的两种解码方式，不作为两个模型计数。

质量依据：[旋律与音符评测](melody-next.md)、[分轨对照](separation.md)、[语音降噪评测](speech-cleanup.md)。安装验证只确认能运行和输出有效，不代表准确率提升。

## 复现与后续

速度脚本：`scripts/benchmark_local_models.py`，参数指定隔离解释器、模型目录、设备和输出目录；需要开发环境中的 psutil。逐项数据发布在 `benchmarks/results/local-hardware-2026-10-17.json`。请同时报告驱动、运行库版本、输入哈希和实际设备，不使用开发者已有 GPU 环境冒充安装版 CPU 结果。

dev17 的 RoFormer/Qwen 自动安装与字词对齐见[操作指南](qwen-and-separation.md)；上面的 dev16 性能数据保留原测量条件，不作为新工具包的速度保证。接下来依次解决：仅处理选中片段、可释放的模型驻留以减少重复等待，以及“哼唱 → 校正 MIDI → 可编辑伴奏 → 编排导出”的完整创作路径。AI 混音、复音转录、可控人声和深度 Agent 仍属于后续工作。
