## 真实模型流程

对已有公开授权示例执行“仅更新歌词”，模型为 Qwen3-ASR 1.7B，时间方式为 small + turbo 双锚点。工作进程、模型加载、识别、时间处理和导出共 **75.16 秒**。界面实际显示了分段进度（3 段识别）及声学时间校准进度；不是以动画代替后端进度。

132.989 秒录音生成 21 个显示段落和 161 个有时间的声学单元。新版本 `8f6795b5812c4865` 通过 `validate_project`；与之前 `f4c471f4b716462c` 相比，以下 7 项 SHA-256 完全一致：原曲、人声、伴奏、原始音高、旋律、节拍、和弦文件。旋律保留 206 个音符，另有 42 个和弦区间、261 个节拍。数量不作为准确率。

另用已保存的 30 秒授权音频执行 `scripts/smoke_test.py`，重新运行真实分离、Whisper small、CREPE、节拍与和弦流程。输出校验通过，墙钟 **62.92 秒**，整卡 1Hz 采样峰值 1031MiB。这个 smoke 使用基础模式，不能与 Qwen 歌词更新耗时直接比较。

## 浏览器流程

- 更新完成后，结果显示“双模型声学锚点”，现有版本仍可比较、切回。
- “下一处核对”会定位到待处理歌词并循环试听上下文。未保存文字时，“已试听核对”给出保存提示；测试文字未写入结果。
- 核对记录保存后刷新仍存在，筛选“已核对”只显示该句；随后取消测试标记，示例恢复为 0 句已核对。
- 用另一模型生成单句候选后，当前版本仍为 `8f6795b5812c4865`。本例候选漏掉句首且产生新错词，保留原版本；关闭后可从待确认入口重新打开。版本列表中的候选先进入比较，不直接覆盖当前结果。
- 跟唱视图显示前后句、当前句及真实词级高亮；灰色文字按句定位。伴奏中加入 15% 原唱提示，保持共享播放位置。
- 从实际界面导出 LRC，得到 21 句，与当前版本结果文字逐句完全一致。
- 工作台在 1280×720 检查了时间轴、歌词、版本栏、播放条与候选入口；窄窗口使用纵向布局。截图来自实际结果与真实播放，不是设计稿。

## 播放稳定性

修复旧服务兼容模式将已有结果反复判成新版本的条件。结果请求按歌曲和实际版本去重；任务状态变化本身不再重置播放器。切歌取消旧音轨请求，晚到的解码结果不能覆盖新歌曲。原曲先可播放，其他音轨首次选择才载入并缓存，旋律合成仅在选择 MIDI 时创建音符声音。

15 分钟本机长曲经历 180 次状态轮询，原曲、人声、伴奏各只请求一次；首次载入伴奏期间原曲时钟继续前进。反复切轨、跳转及快速拖动保持播放。旧服务兼容页面也做了连续播放检查。

## 自动检查与范围

57 项 Python 核心/API 测试、12 项 Node 播放回归测试通过；Ruff 和 JavaScript 语法检查通过。新增检查覆盖自然分句无时间回退、双模型补充的顺序约束、核对记录、候选采用的过期版本防护、分组指标及 bootstrap、下载大小校验、报告硬件来源，以及实际轮询处理函数的去重。

单元测试的 AudioContext 是受控替身；它不能证明分离音色、ASR 文字或主观听感正确。真实音频与 UI 流程验收补充这些检查，但本机上传长曲没有标准答案，不计入准确率表。删除、恢复、导出及并发编辑保护另有 API 回归覆盖。

所有测试音频、识别全文、本机结果、权重与详细日志留在忽略目录。仓库只包含代码、授权示例的界面截图、数据来源和数字报告。
