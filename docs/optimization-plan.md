# 模型、测试集与界面优化计划 · 2026-10-15

> 历史参考：原 Music Studio 歌曲分析流程或拆分前版本。当前工作台请从 [安装与入门](README.md) 开始；原分析产品见 [Music Studio](https://github.com/Hydr0g3ngz/music-studio)。本页的功能、命令与测量按所述旧版本解释。

> 这是早期调研计划。当前已扩展到43例，最新结论见 [歌词 v4](lyrics-v4.md)、[工作台验证](ui-v4-validation.md)，接下来的发布与体验优先级见 [路线图](roadmap.md)。未实测的候选仍保留为未来方向。

这份计划按当前产品范围制定：本地输入歌曲，得到可试听的人声/伴奏、歌词、主唱旋律及和弦节拍，并在同一时间轴上查看。编辑功能只做歌词文字纠错。下一版的主要投入放在自动结果的质量、运行可靠性和查看体验。

## 已落地的测试基础

[固定测试清单](../benchmarks/suite-v1.json) 与 [下载、验证、评分工具](../benchmarks/README.md) 已加入仓库。直接复用四组公开数据的音频及标注，没有新增人工标注。原数据保存在本机 `.artifacts/benchmark/data/`，清单固定上游版本、文件大小和 SHA-256。

26 个样本已通过文件与标注验证，固定 10 个样本已完成现有模型基线。[首轮实测](benchmark-baseline.md) 显示混音歌词和音符起止值得优先优化；它是小规模工程诊断，不代表整个数据集的最终准确率。

| 数据 | 本地子集 | 用途 | 解释范围 |
| --- | --- | --- | --- |
| [Jam-ALT](https://huggingface.co/datasets/jamendolyrics/jam-alt) + [JamendoLyrics](https://huggingface.co/datasets/jamendolyrics/jamendolyrics) | 7 首英文完整混音 | 识别文本与逐词时间 | 用修订后的文本测识别，用对应逐词标注测时间；二者文本并不完全相同 |
| [GTSinger](https://huggingface.co/datasets/AaronZ345/GTSinger) | 中文 6 段、英文 6 段，4 位歌手 | 字词、音符与特殊唱法 | 清唱诊断；不代表成品混音效果 |
| [GuitarSet](https://zenodo.org/records/3371780) | 5 位演奏者、5 种风格的伴奏 | 节拍相位、和弦 | 木吉他伴奏；不代表复杂流行编曲 |
| [MUSDB 七秒预览](https://zenodo.org/records/3270814) | 官方 test 分区 2 段 | 人声/伴奏分离 | 有对应原始分轨；短片段结果不当作整曲成绩 |

这套小集合用于固定回归和筛选方案。已知训练集重叠需要单独标记：例如 [VocalParse](https://github.com/pymaster17/VocalParse) 使用了 GTSinger 训练，[STARS](https://github.com/gwx314/STARS) 也公开了相应训练准备路径。后续比较这些模型时，要增加未见歌曲的确认测试，不能用训练内分数选默认模型。

现成标注也有不同性质：DALI 大量标注来自自动构建；MIR-ST500 发布标注和音频链接，音频版本需要核对；Opencpop 官方下载要求申请。这些都可以扩展，但不作为该实验已经下载并验证的样本来计数。[DALI 原库](https://github.com/gabolsgabs/DALI)、[MIR-ST500 官方说明](https://github.com/york135/singing_transcription_ICASSP2021)、[Opencpop 下载说明](https://wenet-e2e.github.io/opencpop/download/)。

## 模型与算法：推荐比较顺序

| 顺序 | 当前方法 | 优先尝试 | 为什么值得做 | 当前证据状态 |
| --- | --- | --- | --- | --- |
| 1 | Whisper small 直接识别整首分离人声 | 同一模型先改歌唱分段，再比较 large-v3-turbo | 改善漏词、间奏幻觉及长歌重复，优先复用现有推理栈 | small 已有本地基线；新方案待比较 |
| 2 | CREPE 音高 + 阈值/规则切音符 | ROSVOT；RMVPE + 改进切分作为另一条对照 | 音高、音符起止和重复音是不同问题 | CREPE 已测；候选未在本机验证 |
| 3 | librosa 节拍 | Beat This! small0，再比较 final0 | 直接输出节拍和小节起点；部署成本较低 | 仅核对官方实现和模型说明 |
| 4 | Demucs htdemucs | 作者发布的 Mel-Band RoFormer 人声权重 | 改善分离质量，并观察对歌词/旋律是否有实际帮助 | 需要短片段客观分离指标和下游指标一起比较 |
| 5 | STFT 色度模板 + Viterbi 和弦 | 自动估计调音偏移，比较 CQT/CENS 特征及时间平滑 | 首先改善根音和大小调稳定性 | 当前模板法已有可评分基线 |
| 可选 | Whisper 词时间 | SOFA 歌唱对齐；STARS 中英双语方案 | 在已有正确歌词时改善拖音和字词时间 | 需要正确文本/音素输入，不能代替歌词识别 |

### 歌词：先比较处理流程，再选模型尺寸

建议按四组消融试验比较：当前整首人声识别；按歌唱活动切段识别；同样分段下比较混音与分离人声；最后把 small 换成 turbo。每次只改变一个因素，固定语言、音频和评测规则。当前安装的 faster-whisper 已支持 `turbo`，可以保留现有接口；新增模型需固定修订版并实测显存，现阶段不承诺一定改善歌唱识别。[faster-whisper 官方实现](https://github.com/SYSTRAN/faster-whisper)。

分段依据应来自歌唱活动及间奏，而不是直接套用语音 VAD。每段保留上下文边缘，推理后的时间映射回原曲，并去掉重叠重复结果。2025 年的 [Whisper 歌词识别研究](https://arxiv.org/abs/2506.15514) 专门比较了混音、分离人声、原始人声和长短片段，给出了利用分离结果确定长歌边界的方法。这是值得复现的候选流程，不等于本机已得到相同收益。

对连续重复文本、长间奏中的歌词、长时间空白等情况做明确标记。模型分数用于提示待核对，界面不把它显示成正确率。人工修改的歌词也不自动触发整首重新分析。

### 旋律：优先改善音符起止与碎音

[ROSVOT](https://github.com/RickyL-2000/ROSVOT) 的目标就是把歌唱音频转为 MIDI 音符，也提供词边界条件；官方权重用普通话数据训练，其他语言表现仍需本地测试。其公开推理依赖比训练依赖少，应做独立适配试验，保留现在的低显存逐阶段进程方式。

[RMVPE](https://github.com/Dream-High/RMVPE) 是另一种人声音高候选，但单独换音高提取器不能保证音符边界变好。对照试验需分别检查半音抖动、八度误差、相邻同音、漏音、起音偏移和碎音数量。保留原始连续音高曲线，避免只看一个音符总数。

[STARS](https://github.com/gwx314/STARS) 同时处理音素对齐和音符，支持中英模型，但接口要求文字/音素等元数据；现有代码、配置和权重需要配套。可作为第二阶段整合方案，先完成依赖、许可和运行适配核对。

[VocalParse](https://github.com/pymaster17/VocalParse) 的公开 checkpoint 基于 1.7B 解码模型，可以联合输出歌词及音符符号。建议列为探索项，先验证显存、分段长歌和实际时间恢复；它已有 GTSinger 训练重叠，不适合仅凭这组样本升级为默认后端。

### 节拍与和弦：轻量改进也能有明显作用

[Beat This!](https://github.com/CPJKU/beat_this) 官方提供 small 系列约 8.1MB、主模型约 78MB 的权重，并明确代码和权重采用 MIT 许可。先使用不带 DBN 的路径，比较节拍相位、半速/倍速和小节起点；接入前核对候选训练数据与测试样本的重叠。这里的文件大小不是运行显存。

和弦继续保留清晰的大小三和弦/N 输出，先比较调音估计、色度特征、低频信息和持续时间平滑。节拍边界不稳定会传导到和弦切分，需要做“估计节拍”和“固定窗口”的对照。若使用参考节拍诊断，要明确标为理想输入实验，不能混入实际产品成绩。新增七和弦之前，需增加能区分七和弦的指标；大小调简化分数不能证明复杂和弦识别正确。

### 分离：同时看客观指标和下游识别

用 MUSDB 预览比较声源分离 SI-SDR/SI-SDRi，同时在同一批完整歌词歌曲上比较词错误率。更干净的试听音色不必然让 ASR 更好，两个指标都应保留。候选 [Mel-Band RoFormer 作者模型](https://huggingface.co/KimberleyJSN/melbandroformer) 与 [作者实现](https://github.com/KimberleyJensen/Mel-Band-Roformer-Vocal-Model) 可先做可选高质量模式试验。逐个记录具体权重来源和许可，避免把实现代码的许可当作所有社区权重的许可。

## 界面：把查看、核对和导出做顺手

| 优先级 | 界面改动 | 具体行为 / 验收 |
| --- | --- | --- |
| P0 | 歌词文字纠错 | 每句点“编辑”；保存、取消、恢复识别文本；重启后保留；LRC/SRT 使用修改文本 |
| P0 | 改字后的时间语义 | 保留句子原起止；修改过的句子采用句级高亮，标记词时间待更新；不按字数伪造逐字时间 |
| P0 | 更容易试听定位 | 上一句/下一句、单句循环、区段循环、原曲/人声/伴奏/旋律音量控制；切换时保持播放位置 |
| P0 | 结果状态清楚 | 分别显示人声、歌词、旋律、节拍是否完成或失败；可只重试失败/待改善的阶段 |
| P1 | 时间轴可读性 | 显示音名/八度标尺；轨道可折叠；小节信息只在后端真实提供时显示；密集歌词只留必要标签 |
| P1 | 首次使用更顺畅 | 普通界面只选语言和快速/高质量模式；模型下载、大小、进度和缺失提示集中到设置页 |
| P1 | 画面与加载性能 | 原曲先可播放，其他音轨后台就绪；静态波形/音符层缓存，播放指针单独更新；按可见像素抽稀音高 |
| P1 | 导出清楚 | 导出前列出人声、伴奏、歌词、MIDI 的实际可用项；显示歌词是否修改；项目可整体备份/恢复 |

歌词文字纠错可以采用单独的覆盖文件，关联稳定句子 ID，原始识别结果保留。修改文本不需要音符编辑、谱面编辑或重新分离音轨。与原始词时间失配时，明确采用句级展示即可；后续有对齐后端再增加“重新对齐该句”。导出的 JSON 需要保留原词时间的来源及失配状态。

当前页面播放时每帧重绘时间轴，并遍历音高轨迹。先缓存随视窗变化的静态层，只绘制移动指针，能减少长歌界面的 CPU 开销。这属于需要测量的优化方向，尚未提交为已实现性能收益。

## 实施顺序与验收

1. 固定当前基线报告，完成 Windows 异常退出诊断与恢复体验。每次候选比较均记录失败数，不能把失败样本从分母去掉。
2. 做歌词文字覆盖、保存与修订后的字幕导出，以及试听定位改进。
3. 比较歌唱活动分段和 small/turbo；同时验证 ROSVOT 与当前音符切分。新方案先放可选模式，达到同一测试集上的明确收益后再选默认值。
4. 接入轻量节拍候选和时间轴显示，再按实测决定分离与和弦升级的优先级。
5. 在干净环境验证安装和离线启动，跑远程 CI，准备 GitHub 预览版说明及可复现评测结果。

模型升级的通过条件应是：同一固定输入上目标指标改善、其他关键任务没有明显退步、8GB 目标设备能完成、取消/恢复可用、下载及权重来源可复现。具体提升幅度等基线和候选实测后确定，不预填准确率承诺。
